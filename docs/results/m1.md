## Analyze

- **The JDK is not a fair ReDoS baseline any more.** A probe of 8 classic patterns
  (`^(\w+\s?)*$`, `(.*a){12}`, `^(a|ab)*c$`, `(\d+|\w+)*!`, `^([a-z]+)*[0-9]$`, `(x+x+)+y`,
  `^(a+|b+)*c$`, `^(\w+)*@`) on inputs of 10 to 25 repeated characters followed by `#`: JDK 21's
  java.util.regex finished every one in under 3 ms (it memoizes greedy loop positions). An earlier
  version of the bench printed a JDK column for contrast; it showed no blow-up, so it was removed
  rather than presented as a contrast. M3 builds a plain backtracking matcher for the comparison.
- **Defect found:** the first bench header said "no match for any pattern", but `(a+)+$` matches a
  plain run of a's. The input now ends with `!`, and the bench computes its verdict instead of
  printing a fixed sentence.
- **Defect found in a test:** one parser expectation assumed `-` would print as `-`; the
  canonical form prints printable characters as themselves (`[-a]`). The expectation was corrected
  and a case lost while editing (`\w+`) was restored.
